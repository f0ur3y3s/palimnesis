Palimnesis sits between your coding agent and the model. The agent is set to a 1,000,000-token context with its own compaction off, so it always sends the whole conversation. Palimnesis keeps every message and sends the model a bounded view.

Below is one session with a 32K-token model, one step at a time. Each step is a diff. The agent's request is on the left, and what the model receives is on the right. The messages are synthetic. Every size, cache figure and decision comes from running them through the real view builder (eval/walkthrough_sim.py).

    Archive size

    The archive keeps everything, so it grows. Measured on nine sessions (R49), it comes to about 61 KB per request, plus a full copy of the request every 33 requests.

    Budget
    The model gets at most 24,320 input tokens at 32K, after room for the reply. Palimnesis counts with Strata's own template and tokenizer, so the count is exact.
    H and T
    The high and low watermarks. The view stays as it is until it would pass H (about 18,070 here), then old turns collapse until it is below T (about 10,990). The notes and excerpt slots are reserved, so they never count toward either.
    Span
    A run of old turns shown as one line. Every message in it stays in the archive.
    Stub
    An old tool result shortened to its address, size and first and last lines. Palimnesis uses stubs when shortening results is enough. In this session it had to collapse turns instead.
    Working notes
    A short block the model writes just before old turns leave its view. It holds the goal, the constraints, what is done and the next step.
    Excerpts
    Archived text that matches a new message, added to that message in the model's copy only. Picked once and then left unchanged, so Strata's cache stays valid.
