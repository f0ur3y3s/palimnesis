Palimnesis, step by step

A coding session through the proxy with a 32K-token model. The harness keeps and sends the whole conversation. The archive stores every message exactly. The model only ever sees a bounded view: at most 24,320 tokens, and in practice well under it. Token counts are illustrative; the mechanisms are the real ones.

    new this step written by the proxy the model's reply read from Strata's cache watermarks H and T

    1 · Harness sends its whole history, every request

    2 · Proxy archives SQLite, exact, append-only

    3 · Model sees the bounded view sent to Strata

    Terms

    budget
    The most input the model may get: the context size less the output reserve and a safety margin. 24,320 tokens at 32K. Counted with the server's own template and tokenizer, so it is exact.
    H and T
    The high and low watermarks. With F the fixed input (system prompt, tool schemas, the current message) and C the room left in the budget, the view is left alone until it would pass H = F + 0.9·C. Then old turns collapse until it is under T = F + 0.5·C. The gap means the next several turns only append.
    stub
    An old tool result replaced by a line naming its archive address and size, with its first and last lines.
    span
    A run of whole old turns collapsed into one line. Everything in it stays archived exactly.
    working notes
    A short block the model rewrites just before old turns leave its view: objective, constraints, decisions, what is done, the current step, dead ends.
    excerpts
    Archived text the view no longer shows, matched to a new message and appended to it in the model's copy only. Chosen once, then fixed, so the cache keeps working.
    transcripts
    The whole session published as plain files the model can grep and read with its own tools.
