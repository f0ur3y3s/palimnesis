# Papers

Papers motivate mechanisms; `docs/contracts.md` and protocol correctness prevail. A module implementing one of these names it in its docstring with any adaptation.

| Paper | Mechanism Palimnesis takes | Phase | Not taken / adapted |
| --- | --- | --- | --- |
| [ARC](https://arxiv.org/html/2607.25066v1) | Observation masking with exact addressable recall; bounded catalog pages; paired-outcome (McNemar) analysis | 2, 3, 7 (recall tools and model-facing catalog navigation: optional 3B, A1) | Active-view assumptions are checked against the proxy's budget contract, not adopted wholesale |
| [LCM](https://arxiv.org/html/2605.04050v1) | Immutable history; optional hierarchical summary DAG; escalation detailed → bullets → deterministic; memory tools | 1, 5 | "Zero-cost continuity" concerns short-task recursive overhead, not prefix-cache guarantees |
| [The Complexity Trap](https://arxiv.org/abs/2508.21433) | Deterministic masking is competitive with LLM summarization; scaffold-dependent evaluation | 2, 7 | — |
| [Eunoe](https://github.com/chroxify/eunoe) (MIT; software, not a paper) | Proactive recall: before each user message is answered, BM25 over archived content no longer in context, with matches quoted exactly in a delimited block appended to that user message, computed once and pinned so the prefix cache holds; readable per-session transcript files (`index.md` plus `turn-NNNN.md`) searched by the agent through a short recipe when recall misses | 2, 3 (A1) | **Evidence limits:** Claude Code with Anthropic models; ~110K-token prompts (the README's "prompt size when asked"); 24 held-out sessions of 90–120 turns from one developer; one run per arm; 600 planted facts scored by exact match; the answering model is unnamed; vague references are a stated weakness. It does not establish results at 32–64K with local models. **Adaptations:** budgets at 32–64K with per-message and total excerpt caps that may fall to zero; whole-block deterministic omission with recorded invalidations; a different deterministic query construction (D28): Eunoe lowercases the prompt, keeps terms of 3+ characters matching its own term pattern outside a 66-word stopword list, keeps compound tokens alongside their parts, and runs one query per prompt line (top 12 each), with an optional reranker; Palimnesis runs one OR query of at most 32 terms, code-like terms first, compound runs as phrases of their sub-tokens, a 2-character minimum, no per-line queries and no reranker; a different relevance floor (D29.2: Eunoe requires min(2, wanted) matched terms; r1 also admits one code-like term alone); chunks of 24 lines / 1,536 code points over every block kind instead of Eunoe's 6-line windows of tool results with the call description folded in (D27); reasoning blocks are searched too; search over every archived span absent from the resulting view, including user messages; Eunoe searches tool outputs no longer in context plus what the agent said while working; transcripts as a crash-safe, rebuildable projection of the immutable archive; a harness capability gate before claiming transcript fallback. The a3 recipe inverts Eunoe's "skim index.md, read the whole turn file": whole-file reads overflowed a 64K context (D37.1). **Not taken:** cross-session recall; Eunoe's subagent transcript files and its `## User` / `### [tool i/n]` headings; Eunoe's own context folding (a ~100K budget keeping the last 3 turns with verbatim evidence lines); its cache safety rests on changing the prefix only at a fold, which Palimnesis's threshold events (D20.1) mirror |
| [RaMem](https://arxiv.org/abs/2606.22844) | Contextual evidence (neighbors, provenance) and retrieval validity | 6 | Principles only; not its full long-term-memory framework |
